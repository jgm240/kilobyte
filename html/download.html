Download

Which file?

64-bit PC (x64; most PCs since 2007, Intel Macs)...-amd64-usb.img for a USB stick, or ...-amd64.iso
32-bit PC (i386)...-i386-usb.img or ...-i386.iso; a PC that only starts from CDs: ...-i386-cd.iso
Raspberry Pi 2 or newer...-raspberrypi-arm64.img.xz (Pi 3, 4, 400, 5, 500, Zero 2 W); Pi 2: ...-raspberrypi-armhf.img.xz
Raspberry Pi 1...-raspberrypi-armel.img.xz
Raspberry Pi Zero, Zero W...-raspberrypi-armel.img.xz
Kindle (jailbroken)kilobyteink-....zip

Not sure whether a PC is 64-bit? Windows says it in Settings > System > About ("System type"); on Linux, "uname -m" says x86_64.

The files

From GitHub: Kilobyte 1.4, Kilobyte for Mac 1.5, Kilobyte 1.3, KilobytEink 1.5.

  • kilobyte-1.4-amd64.iso: 64-bit PC (ISO), 994 MB
  • kilobyte-1.4-amd64-usb.img: 64-bit PC (USB stick), 1.0 GB
  • kilobyte-1.5-amd64-mac-usb.img: Intel Mac (USB stick), 1.1 GB
  • kilobyte-1.5-amd64-mac.iso: Intel Mac (ISO), 1.1 GB
  • kilobyte-1.3-i386.iso: 32-bit PC (ISO), 701 MB
  • kilobyte-1.3-i386-usb.img: 32-bit PC (USB stick), 749 MB
  • kilobyte-1.4-i386-cd.iso: CD version, for PCs from the 1990s, 502 MB
  • kilobyte-1.4-raspberrypi-arm64.img.xz: Raspberry Pi 3, 4, 400, 5, 500, Zero 2 W, 489 MB
  • kilobyte-1.4-raspberrypi-armhf.img.xz: Raspberry Pi 2, 3 (32-bit), 495 MB
  • kilobyte-1.4-raspberrypi-armel.img.xz: Raspberry Pi 1, Zero, Zero W, 357 MB
  • kilobyteink-1.5.zip: KilobytEink, for jailbroken Kindles, 230 MB

Each file has a .sha256 checksum next to it on the release pages, with the list of source packages of each image.

PCs

USB stick: write the -usb.img file (or the ISO) to the stick with balenaEtcher, Raspberry Pi Imager ("Use custom"), or on Linux and macOS:

sudo dd if=kilobyte-1.5-amd64-usb.img of=/dev/sdX bs=4M status=progress

CD: burn the CD version's ISO as an image (not as a file). Virtual machine: start the ISO in QEMU, VirtualBox or UTM. Kilobyte runs from the stick or CD; "Install Kilobyte to disk" in the Program Manager puts it on the hard disk (the CD version can also keep Windows 98 next to it).

Tested on:

  • MacBook Pro Late 2008 (made about 2008): 64-bit, the Mac version's USB stick image
  • Medion Akoya E6240 (made December 2014): 64-bit, the USB stick image
  • Sony VAIO PCG-71811M (made about 2011): 32-bit (i386), the ISO

Intel Macs

The Mac version is the 64-bit version plus what Intel Macs (2006 to 2015) need: Broadcom's Wi-Fi driver, F1-F12 as F-keys, and fans that run by temperature.

USB stick: write the -mac-usb.img file with balenaEtcher, or in the Terminal (diskutil list shows which disk the stick is):

diskutil unmountDisk /dev/diskN
sudo dd if=kilobyte-1.5-amd64-mac-usb.img of=/dev/rdiskN bs=4m

Then hold Option at the start-up chime and choose "EFI Boot". If the screen stays on the boot menu's picture, start again and choose "Kilobyte (Mac: graphics driver off)", or else "Kilobyte (Mac: firmware screen only)".

Macs with Apple's own chips (M1 and newer) cannot start Kilobyte; Transition puts it next to macOS instead.

Raspberry Pi

Write the .img.xz file to a memory card with Raspberry Pi Imager ("Use custom") or balenaEtcher; no need to unpack it. The first start asks for keyboard, time zone, name and password, and makes the system fill the card.

KilobytEink (Kindle)

For a jailbroken Kindle with the Universal Hotfix (scriptlets) and kterm. Copy the folders documents and kilobyteink from the ZIP to the Kindle's main folder over USB; "KilobytEink" then shows up in the Library. The ZIP's README.txt has the details.

Already have Debian?

Debian, Ubuntu or Raspberry Pi OS keep their desktop and get Kilobyte next to it: one line.
